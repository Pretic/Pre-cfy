# Pre-cfy 系统加固设计

日期：2026-08-16

## 目标与范围

本轮仅维护 `cfy.sh`、Shell 测试和文档。目标是提高候选质量、重复运行稳定性、安装更新可靠性，以及与 Sing-box-Pre 的订阅协作，同时保持脚本轻量、通用且适用于普通 VPS、端口受限 NAT、IPv4/IPv6 单栈和双栈。

cfy 仍是按需执行的生成工具，不成为常驻服务，不进入节点数据转发链路。

## 不变约束

- 保留 VLESS-first、VMess 兼容的模板识别。
- 保留当前数量策略：双栈时每运营商/地址族最多 3 个，IPv4 在前；单栈最多 5 个；质量不足不硬凑。
- 不自动定时测速，不自动更换用户订阅。
- 不要求所有用户使用作者域名、API token 或固定 Tunnel。
- 不依赖数据库、Web 服务或额外常驻进程。

## 设计

### 1. 安装与更新

通过可读的普通文件或进程替换运行时，安装当前正在执行且已经下载完成的脚本，不再二次访问 GitHub Raw。stdin 管道无法可靠重读时才使用明确的远端下载路径。

安装和更新统一采用“同目录临时文件 → 标识校验 → `bash -n` → `install` 原子替换”，失败时保留旧版本。更新过程不得改动已有订阅和候选结果。

生成模式在交互前确认 root 权限；`--check` 保持只读，并在文件不可读时给出明确提示。

### 2. 模板来源优先级

先只读取 Sing-box 拥有的 `url.txt`。只要其中存在有效的 VLESS-WS-TLS-Argo 或 VMess 模板，就不得读取旧 `cfy-url.txt`、`all-url.txt` 或 `sub.txt` 作为候选模板。

仅当基础文件不存在、为空或没有有效模板时，才按固定顺序读取回退来源，并精确去重。这样第二次运行不会在旧优选节点上继续派生。

### 3. 候选解析与地址校验

IPv4 必须校验每个 octet 为 0–255；IPv6 必须通过可靠解析或严格语法检查；端口必须为 1–65535；域名禁止空 label、连续点、非法字符和非法端口。

第三方 HTML 解析失败、列错位或缺少延迟时不生成伪候选。远端请求均设置连接和总超时，失败时说明具体数据源，不无限等待。

### 4. 地址族与数量

自动模式分别探测 IPv4 和 IPv6 的实际出站能力。显式 `CFY_IP_VERSION_SCOPE` 继续覆盖自动结果。若两种探测都失败，脚本明确提示并使用保守 IPv4 回退，不伪称已检测成功。

排序继续以运营商、地址族和 RTT 为依据；IPv4 组始终在 IPv6 组前。每组只输出真实存在并通过校验的候选，不补齐失败项。

### 5. 候选健康检查

云优选 VLESS 候选默认执行一次轻量 WS/TLS 回源检查；它只验证 edge 能否正确到达原有 host/SNI/path，不测试大文件速度，也不影响日常节点流量。高级用户可通过环境变量关闭或调整尝试次数。

探测参数必须限制在安全整数范围内。系统性网络故障与单候选失败要区分：候选失败会被跳过；无法执行任何有效探测时给出失败原因，不把未验证候选标记为健康。

健康检查只作用于本次生成结果；没有足够健康候选时减少输出，不硬凑数量。

### 6. 与 Sing-box 的发布契约

cfy 只拥有 `cfy-url.txt` 和 `cfy-sub.txt`。综合发布使用双方约定的 `/etc/sing-box/.subscription.lock`，在锁内从 `url.txt` 和 `cfy-url.txt` 精确去重生成：

- `all-url.txt`：内部明文，`0600`；
- `all-sub.txt`：内部 Base64，`0600`；
- `sub.txt`：对外 Base64，`0644`。

三个文件必须源于同一份临时明文。任一步失败不发布半套结果，旧订阅继续可用。空候选只更新 cfy 自有结果，不清空有效的基础订阅。

### 7. 并发、清理和历史

生成过程注册统一临时资源清单，并在 EXIT、INT、TERM 中清理本次创建的临时文件。信号退出码保持非零且不覆盖已有有效订阅。

结果历史按数量上限轮换，默认保留最近 20 份；环境变量可以设置一个经过夹紧的合理范围。并发运行时只有持有共享锁的进程可以发布综合订阅。

所有数值环境变量在使用前验证和夹紧，避免超大循环、算术异常或意外资源消耗。

## 错误处理

- 下载、解析、探测、写入、Base64 和发布任一步失败都返回非零并指出阶段。
- 生产文件只通过同目录临时文件原子替换。
- 旧结果在新一轮完全成功前保持可读。
- 日志不得输出完整订阅密钥以外的额外凭据；默认展示节点链接的既有行为不变。

## 测试与验收

- 模板来源测试覆盖首次运行、第二次运行、基础模板变化和回退来源。
- 地址测试覆盖非法 IPv4 octet、无效/带端口 IPv6、非法域名和端口边界。
- 健康探测覆盖健康、失败、超时、系统性网络故障和参数夹紧。
- 地址族测试覆盖 IPv4 单栈、IPv6 单栈、双栈、显式覆盖和探测全失败。
- 数量测试保持双栈 3+3、IPv4 在前，单栈 5，质量不足不补齐。
- 发布测试覆盖共享锁、并发、部分写失败、精确去重、Base64 一致性与 `600/644` 权限。
- 安装测试覆盖进程替换不二次下载、下载内容语法错误、原子回滚和离线查看旧结果。
- 中断测试确保临时文件清理、旧订阅保留和非零退出。
- 历史轮换测试确保只保留配置数量。

## 发布策略

在隔离分支完成、运行全部测试并经过独立审查后合并到 `main` 并推送。当前 VPS 只替换经过验证的 `/usr/local/bin/cfy`，不自动执行生成；部署后用 `cfy --check` 和文件权限检查验证，不改变现有候选节点。
