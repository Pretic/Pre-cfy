# Nginx 订阅文件权限修复设计

## 问题

`cfy` 使用限制性 `umask` 和原子写入保护订阅文件，但最近的权限加固把 Nginx 通过 `alias` 发布的 `SERVED_SUB_FILE` 也设为了 `0600`。Nginx worker 通常不是 root，因此更新订阅后会返回 HTTP 403。

## 设计

- 内部明文与 Base64 文件继续默认使用 `0600`。
- `write_base64_file` 接受可选的第三个权限参数，默认仍为 `0600`。
- `sync_combined_subscription` 只在写入 `SERVED_SUB_FILE` 时显式使用 `0644`。
- 临时文件在写入和移动前设置最终权限，保留原子替换行为，避免短暂暴露半写入内容。
- 不改变订阅内容、优选逻辑、网络路由或 Sing-box 配置。

## 兼容性与安全边界

`0644` 与现有 Sing-box/Nginx 部署方式兼容，也不依赖发行版特定的 Nginx 用户或组。订阅的访问控制仍由随机路径和 Nginx 配置承担；同机非特权用户可读取发布文件，这是当前通用部署兼容性的明确取舍。内部文件仍保持 `0600`。

## 验证

- 回归测试断言内部 Base64 输出为 `0600`、发布文件为 `0644`。
- 结构测试断言只有 `SERVED_SUB_FILE` 调用显式请求 `0644`。
- 在 Linux 上运行完整测试并通过本机 Nginx 回环请求验证不再返回 403。
